Case 01 · internal AI product · Microsoft Copilot Studio

ACD Internal AI support chatbot

An internal support agent that answers the questions the documents already answered, and names the ones it must not touch.

Problem

Tier 1 volume was answerable-by-document. The same forty questions arrived in a hundred phrasings (licensing, entitlements, which contract document applies), and agents were acting as the search interface for content that already existed.

My role

Product owner, end to end. I designed the intent taxonomy, ran the SME sessions that produced the knowledge sources, built and iterated the agent in Copilot Studio myself, and owned the post-launch feedback loop rather than handing it to support.

Approach

01

Taxonomy from tickets, not org charts

I clustered a real ticket sample by what the resolution required, not by product area. Each intent got one owner and one source of truth, so an unanswered question always had an address.

02

Knowledge structured with SMEs

Authority documents were written for people, not retrieval. Working session by session with SMEs, we restructured them into scoped, retrievable sections with explicit boundaries, and wrote the refusal path for anything legal-adjacent.

03

A loop that changes something

In-conversation feedback plus unresolved-intent logging fed a weekly triage with exactly three outcomes: fix the source, extend the taxonomy, or route the topic to a human for good. Failures became a maintained backlog instead of a mystery.

Taxonomy, abridged
Intent cluster Source of truth Resolution path
Licensing & seat questions Licensing policy set Self-serve answer, cited
Which contract document applies Document family guide Guided answer, scope-bounded
Account & entitlement Support knowledge base Self-serve; exception escalates
Legal interpretation of terms None (by design) Explicit refusal → human
Outcome

Tier 1 dependency dropped on every intent the taxonomy covered. Conversations closed without an agent, and the intents it could not close were named, owned and dated instead of staying invisible.

Case 02 · prototype · built with Claude Code & Claude Design

Beacon

A student learning dashboard where the three surfaces feed each other: the radar says what's weak, the cards say what to do next, the tutor does the teaching, and what happens in the tutor moves the radar.

Built as a static HTML prototype so the loop could be argued about in a browser instead of a deck. Claude Code for the build, Claude Design for the interface: the same workflow I'd use to de-risk a spec on day three of discovery, not day thirty.
